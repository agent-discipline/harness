### N14. 한 세션이 작업 여럿을 나란히 할 때의 게이트 — 우선순위: 높음 · 관측 신호: 2026-11-27~28 실측(deploy-study-note 세션 — 사용자 지시 "하네스 next에 적어놔줘")

- **무엇이 일어났나**: 메인이 새 작업 폴더(`study-note/docs/plans/2026-11-27/study-site-import/log.md`)를 Write 로 열자 세션의 상태 파일이 `SPEC=0 · MODE=UNSET` 으로 리셋됐다(설계대로 — core §1). 상태 파일은 세션에 하나라, **이미 합의되어 진행 중이던 다른 작업 셋**(하네스 close-out-requirement-check · claude-fallback 조각 8 · visit-tracking V6a)의 L1 쓰기도 함께 막혔다. 워커들은 저장소 밖 사본에서 일하고 patch 로 떠 두었다(작업 트리로 옮기기 · 커밋만 밀림 — 반나절).
- **왜 풀리지 않았나**: 새 작업의 명세를 사용자가 합의한 뒤 메인이 `set-state.sh spec-approved` 를 실행했으나 Claude Code 의 auto 모드 권한 판정이 **두 번 거부**했다(사유 `[Undermining Oversight]`). 앞 작업을 위해 되돌리려던 실행도 같다. 사용자가 프롬프트에서 `!` 로 직접 실행해야 풀린다 — 사용자가 "1단계가 왜 필요한거야?"라고 되물었다(절차가 사용자에게 보이지 않았다).
- **이번 작업(v4.x close-out)이 고친 것과 남은 것**: 워커(agent_id)의 Write 로는 리셋되지 않게 됐다(task 05). **메인의 Write 로 인한 리셋은 그대로다** — 한 세션 = 한 작업이라는 전제가 남아 있다.
- **방법론 선택지**:

| 방안 | 요지 | 비용 | 실패 모드 | 맞는 조건 |
|------|------|------|----------|----------|
| A | 합의 상태를 **작업 폴더마다** 둔다(상태 파일에 `TASK_PATH` 별 `SPEC` · `MODE` — 쓰려는 파일이 어느 작업의 것인지는 워커 브리핑의 작업 폴더 · 사이드카 `req-check-paths` 와 같은 꼴로 가린다) | 훅 셋(gate-guard · task-mode-guard · set-state) + 스키마 5 · 높음 stakes | 쓰는 파일 → 작업의 대응을 훅이 알 수 없는 경우(같은 저장소를 두 작업이 고침) → 보수적으로 막으면 지금과 같다 | 한 세션에서 작업을 나란히 돌리는 것이 보통일 때(지금) |
| B | 리셋할 때 직전의 `SPEC=1` 작업을 "진행 중 목록"에 남기고, `set-state resume <작업 폴더>` 로 되돌린다(되돌리기는 사용자 확인 뒤) | 훅 둘 · 중간 | 되돌린 동안 새 작업의 게이트가 열린 것처럼 보인다(절차 규칙으로만 막음) | 작업 전환이 드물 때 |
| C | 훅은 그대로 두고 절차만: 새 작업 폴더는 **앞 작업의 L1 이 모두 커밋된 뒤에** 연다 · 급하면 새 세션에서 | 문서 한 줄 | 사용자가 중간에 새 일을 맡기면(이번처럼) 지켜지지 않는다 | 임시 방편 |

- **함께 정할 것**: `set-state.sh` 를 메인이 실행하는 길이 auto 모드에서 막힌다 — ① 사용자의 설정에 `Bash(bash ~/.claude/hooks/set-state.sh:*)` 허용 규칙을 두도록 README 에 안내한다 ② 합의의 기록을 `capture-decision`(AskUserQuestion 의 답을 받는 훅)이 **사용자의 답에서 직접** 하게 한다(선택지 "합의 — auto"를 고르면 훅이 `SPEC=1 · MODE=auto` 를 쓴다 — 모델이 스스로 게이트를 여는 꼴이 아니게 된다). ②가 맞는 방향으로 보인다(판정 장치가 막는 까닭과도 맞는다) — 선택지의 글에 기대는 판별이 약점이다.
- **발생 가능 문제**: A 는 "닫기 전 요구 대조"의 사이드카와 상태가 둘로 나뉜다 — 하나로 합칠지 먼저 정한다 · 압축 뒤 재독의 대상(`reread-track`)도 작업 폴더가 여럿이 된다.
- **대처**: 그때까지는 C 로 일하고(새 작업 폴더를 열기 전에 앞 작업의 patch 를 커밋한다), 사용자에게 `!` 로 실행할 두 줄을 **까닭과 함께** 먼저 보인다.
