## 1. 목표·대상 (필수)

하네스 저장소(`agent-discipline/harness`)에서 세 가지를 고친다.

1. **전체 읽기만 인정**: 압축 뒤 재독 판정에서 `offset`이나 `limit`이 붙은 Read는 읽은 것으로 세지 않는다.
2. **인터뷰 전 작업 폴더 생성**: 새 작업은 작업 폴더의 `log.md`를 먼저 만든 뒤 인터뷰를 시작한다는 절차를 core.md에 넣는다. 훅 코드는 바꾸지 않는다.
3. **남은 기록 알림**: 세션을 새로 시작할 때, 같은 상태 디렉토리의 직전 세션이 쓰던 작업 폴더에 커밋되지 않은 변경이 있으면 훅이 한 줄로 알린다. 그 줄을 본 메인이 사용자에게 이어갈지 묻는 절차를 core.md에 넣는다.

끝의 기준: 테스트 전체 통과, 배포와 smoke 통과, 실제 세션에서 1번(부분 읽기 뒤에도 차단 유지, 전체 읽기 뒤 해제) 확인. 3번은 훅을 직접 실행해 출력을 확인하고, 실제 새 세션에서의 확인은 다음 세션에서 한다.

## 2. 경계·불변식 (필수)

- **I1 전체 읽기 판정**: `reread-track.sh`는 `tool_input.offset` 또는 `tool_input.limit`이 값으로 들어온 Read(JSON `null`과 필드 없음은 "없음"으로 본다)를 `.reread`에 기록하지 않는다. 둘 다 없는 Read만 기록한다. 세션 표시(`<sid>.reread-seen`)는 종전대로 부분 읽기에서도 만든다.
- **I2 차단 문구**: 미독 차단 stderr의 끝줄을 `(offset·limit 없이 파일 전체를 Read 해야 인정)`으로 바꾼다. 그 밖의 문구와 차단 조건은 그대로다.
- **I3 절차(문서)**: core.md 1절에 "새 작업은 작업 폴더의 `log.md`를 먼저 만들고 인터뷰를 시작한다(질문과 답이 그 폴더의 `decisions.md`에 기록되게)"를 넣는다. `log.md` 생성이 게이트 상태를 초기화하는 종전 동작은 그대로다. 상태 전이 그림과 세션 시작 안내문(`session-mode-guard.sh`의 `MSG`)의 순서 서술도 이에 맞춘다. (2026-11-20 리뷰 반영으로 추가: SPEC=0 차단 안내의 복구 순서(`gate-guard.sh`)와 README의 작업 흐름 그림도 같은 순서로 맞추고, `log.md`는 Write 도구로 만든다고 적는다 — 훅은 Write 도구로 만든 것만 본다.)
- **I4 남은 기록 알림**: `session-mode-guard.sh`는 `source=startup`일 때만 다음을 한다. 같은 상태 디렉토리에서 현재 세션이 아닌 상태파일 중 가장 최근에 고쳐진 것 하나를 고르고, 그 `TASK_PATH`가 비어 있지 않은 실제 디렉토리이면 그 폴더에 대해 `git status --porcelain`을 본다. 변경이 있으면 종전 출력 뒤, 고정 지시 앞에 다음 한 줄을 낸다.
  `[게이트] 직전 세션의 작업 폴더에 커밋되지 않은 변경이 있습니다: <TASK_PATH> — 사용자에게 이어갈지 물으세요(이어가기 / 기록만 커밋 / 되돌리기).`
  훅은 알리기만 한다. 파일을 고치거나 git 상태를 바꾸지 않는다.
- **I5 알림의 실패 방향**: 직전 세션을 못 찾음, `TASK_PATH` 없음·디렉토리 아님, git 저장소 아님, git 실행 실패·시간 초과(2초)는 모두 "알림 없음"이다. 어떤 경우에도 세션 시작을 막지 않고 종전 출력은 그대로 나온다. `resume`·`clear`·`compact`·`fork`에서는 이 검사를 하지 않는다.
- **I6 절차(문서) — 남은 기록의 처리**: core.md 7절에 "세션 시작 때 이 알림을 보면 사용자에게 세 가지 중 하나를 묻는다 — 이어가기 / 기록만 커밋 / 되돌리기. 되돌리기는 사용자가 고른 뒤에만 한다"를 넣는다.
- **I7 기존 계약 보존**: 그 밖의 훅 동작(게이트, 재독 차단 조건, 고정 지시 주입, 압축 시각 기록)과 기존 테스트는 그대로다. 바뀌는 테스트는 `dr_rr_14`(뜻이 뒤집힘)와 차단 문구 끝줄을 확인하는 테스트뿐이다.

## 5. 검증 방법 (필수)

- 테스트는 명세에서 먼저 쓴다(구현 전에 실패 확인). 새 케이스: I1(offset만, limit만, 둘 다, `null`, 없음), I2(끝줄 문구), I4(변경 있음 → 한 줄, 변경 없음 → 없음, 가장 최근 세션만 봄, 현재 세션 제외), I5(각 실패 방향에서 알림 없음과 종전 출력 유지, `startup` 밖에서는 검사 안 함), I7(`dr_rr_14` 뒤집기).
- `bash hooks/tests/run.sh` 전체 통과(lock 재생성 사유 기록).
- 듀얼 1패스 리뷰(Opus 워커 ∥ codex) + 수정분 재점검.
- 배포 → smoke → 실제 세션 확인: 이 세션은 압축을 겪었으므로, 작업 기록을 `limit`을 붙여 Read 한 뒤 L1 쓰기를 시도해 막히는지 보고, 전체 Read 뒤 풀리는지 본다. 4번은 `startup` 입력을 넣어 배포된 훅을 직접 실행해 출력을 본다.

## 8. load-bearing 가정 (1~2개)

1. Claude Code는 `offset`·`limit` 없이 Read 할 때 훅 입력의 `tool_input`에 그 두 필드를 넣지 않거나 `null`로 넣는다 — 착수 직후 실제 세션에서 전체 읽기와 부분 읽기를 한 번씩 하고, 임시 덤프 없이 확인할 방법(배포 전에는 `probe/post-read.json` 표본, 배포 뒤에는 `.reread` 기록 여부)으로 확인한다.
2. 새 세션의 SessionStart(`startup`) 시점에 같은 상태 디렉토리의 이전 세션 상태파일이 남아 있다(30일 정리 전) — 현재 상태 디렉토리의 실제 파일로 확인됨(2026-11-17 세션 파일들이 남아 있음).
