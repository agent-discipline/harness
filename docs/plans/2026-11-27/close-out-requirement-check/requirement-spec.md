## 1. 목표·대상 (필수)

하네스 저장소(`agent-discipline/harness`)에서, **메인이 task 를 닫기 전에 그 task 의 요구를 줄마다 결과(file:line · 커밋)나 넘긴 곳(받는 task · 사용자 합의)에 대어 log 의 "요구 대조" 표로 남기고, 빈 칸이 있으면 닫지 않게** 한다 — 규칙 문서(core §4 · `task-units.md` §3 · 두 템플릿)와 훅(state-lib 의 표 파서 · gate-guard 의 차단 · reinject-mode 의 알림 · 테스트)으로. 덤으로(Q8 (가)면) task-mode-guard 가 워커의 Write 로 메인의 게이트를 리셋하지 않게 한다.

## 2. 경계·불변식 (필수)

- **차단(gate-guard)**: 훅이 보는 작업 폴더의 log.md 에 요구 대조 표가 있고, 상태 칸이 `닫음`인 줄의 "만든 곳 / 넘긴 곳" 칸이 비어 있으면, 그 세션의 PreToolUse L1 쓰기(Edit · Write · MultiEdit — 메인과 워커 모두)를 막는다(exit 2 · 막힌 task 와 줄을 알린다). DEBT=1 이면 막지 않고 알린다.
- **표를 고치는 길은 막히지 않는다**: log.md 는 L0(docs) 라 이 검사보다 먼저 통과한다(gate-guard 의 L0 판정이 앞 — `gate-guard.sh:319-321`).
- **판정 불가는 막는다(C2 ②)**: 표의 표지(marker)가 있는데 머리 줄 · 칸 수 · 상태 값이 꼴과 다르거나 log.md 를 읽을 수 없으면 PreToolUse L1 쓰기를 막고 무엇이 틀렸는지 한 줄로 알린다. **표지가 없으면 검사하지 않는다**(옛 작업 폴더 — 대상이 아님).
- **알림(reinject-mode)**: 상태가 `열림`이고 빈 칸이 있는 task 마다 "빈 칸 / 줄 수"를 매 턴 한 줄로. 빈 칸이 없으면 출력 없음(종전 출력과 바이트까지 같다).
- **파일을 끝까지 읽는다**: 파서는 log.md 를 앞부분만 읽지 않는다(사고의 log 는 139KB — 절단은 이 사고의 원인이었다).
- 기존 동작은 그대로: SPEC · MODE 게이트 · lazy PENDING · 압축 뒤 재독 · 구현 주체 알림 · 상태파일 거부 · 고정 지시. 표가 없는 세션의 모든 훅 출력은 바이트까지 같다.
- (Q8 (가)) task-mode-guard: `agent_id` 가 있는(비어 있지 않은 문자열) Write 는 상태를 바꾸지 않는다. 없거나 빈 값 · null 이면 종전대로(gate-guard `reread_gate` 와 같은 기준).
- 규칙 문서: `src/core.md` ≤ 15,404자(README 세는 법) · 조건부 문서 ≤ 80줄 · 옮긴 문장의 대조표(`rule-docs.md` 규칙 6)에서 옮긴 뒤 위치가 빈 것 0 · 단일 출처(표의 꼴 = log 템플릿, 쓰는 법 = `task-units.md` §3, 훅이 보는 것 · 못 보는 것 = README).
- 가로지르는 계약: log 템플릿의 표 머리 줄(글자 그대로) ↔ state-lib 파서의 머리 줄 상수 ↔ 테스트 고정 자료 ↔ `task-units.md` §3 의 상태 값(`열림` · `닫음`) ↔ core §4 의 줄 ↔ README 의 훅 설명 · 한계. 하나를 바꾸면 넷을 함께.

### 6.1 훅 설계 — 쓰기를 지켜보지 않고 상태(표의 글자)를 읽는다

초안 1 의 반대 근거 둘을 푸는 방식:
- "메인이 log 를 Bash heredoc 으로 써서 훅이 못 본다" → **log.md 쓰기를 관찰하지 않는다.** 훅이 판정할 때마다 log.md 의 지금 내용을 읽는다. 어떤 도구로 썼든 내용은 같다.
- "'닫음'이 자유 글이라 판별이 흔들린다" → **타임라인의 글을 읽지 않는다.** 닫음은 표의 상태 칸에 정해진 값(`열림` · `닫음`)으로만 적고, 훅은 그 칸만 읽는다.

① 표의 꼴(템플릿이 정본 — 훅이 글자 그대로 맞춘다):

```text
<!-- req-check:v1 -->
| task | 원문 위치 | 요구 | 만든 곳 / 넘긴 곳 | 상태 |
|---|---|---|---|---|
| T4 | 규약 §7.1 · 478행 | ci-cd 마스터·에이전트가 3.4 의 줄을 표준 출력에 쓴다 | | 열림 |
```

- 표지 줄 다음의 첫 표 하나만 읽는다. 머리 줄은 글자 그대로(앞뒤 공백 무시). 칸은 다섯 — 칸 안의 `\|` 는 칸 경계가 아니다. 상태 ∈ {`열림`, `닫음`}. 빈 칸 = 비었거나 공백뿐이거나 `-` · `—` · `?` 하나뿐.
- 줄 판정: 상태 `닫음` 이고 4번째 칸이 빈 칸 → **위반**. 상태 `열림` 이고 4번째 칸이 빈 칸 → **열린 빈 칸**(알림만).

② 언제 읽고 무엇을 하나:

| 자리 | 언제 | 읽는 것 | 하는 것 |
|---|---|---|---|
| gate-guard `req_check_gate`(새 함수) | PreToolUse · L1 판정 뒤 · SPEC/MODE 게이트를 통과한 뒤 · auto 와 lazy 둘 다(lazy 는 PENDING 판정 앞) · 메인과 워커 모두 | 훅이 보는 작업 폴더(Q7)의 log.md | 위반 → exit 2(task · 줄 번호 · "표를 채우거나 상태를 열림으로 되돌린다") / 판정 불가 → exit 2(틀린 곳 한 줄) / DEBT=1 → 막지 않고 stderr 한 줄 + additionalContext / 표지 없음 · 위반 없음 → 종전 흐름 |
| reinject-mode | 매 턴(UserPromptSubmit) | 같은 log.md | 열린 빈 칸이 있는 task 마다 `T4 7/13` 꼴로 한 줄(최대 5 task + "외 N") · 위반이 있으면 그 줄을 앞에 · 판정 불가면 "요구 대조 표 판정 불가: <까닭>" 한 줄 · 그 밖에는 출력 없음 |
| state-lib `state_reqcheck_scan`(새 함수) | 위 둘이 부른다 | log.md 전체(`awk` 한 번 — 줄 상한 없음) | 출력 `VIOLATION\t<task>\t<줄 번호>` · `OPEN\t<task>\t<빈 칸>\t<줄 수>` · rc 0 판정 · rc 1 판정 불가(stdout = 까닭 한 줄) · rc 2 표지 없음 |
| (Q7 (나)) task-mode-guard | 메인의 Write 로 `docs/plans/*/log.md` 가 생길 때 | — | 상태 디렉토리의 `<sid>.req-check-paths` 에 그 작업 폴더(canonical) 한 줄을 더한다(중복 없음 · 원자 쓰기 — worker-notice 사이드카와 같은 관례). gate-guard · reinject 는 이 목록의 폴더 전부 + TASK_PATH 를 읽는다 |

③ 표가 없을 때 · 긴급 · lazy · 오탐:
- 표지가 없는 log(옛 작업 폴더 · 표를 아직 만들지 않음) → 검사하지 않는다. 새 작업 폴더의 표 만들기는 절차 규칙이다(task-units §3) — 훅은 표를 만들게 하지 못한다.
- 긴급(DEBT=1) → 위 표대로 알림만.
- lazy → 같은 검사. 표를 채우는 쓰기(log.md)는 L0 라 PENDING_GATE 도 세우지 않는다(종전과 같음).
- 오탐(파서가 맞는 표를 틀렸다고 함) → 막힌 메시지가 틀린 곳(줄 번호 · 까닭)을 보인다. 푸는 길은 표를 고치는 것(log.md 쓰기는 막히지 않는다). 파서 자체의 결함이면 사용자가 표지 줄을 지워 그 폴더의 검사를 끈다 — 이 길은 log 의 diff 로 남는다. **환경 변수 · set-state 명령으로 검사를 끄는 길은 만들지 않는다**(메인이 스스로 쓸 수 있는 우회가 된다 — 상태파일 거부와 같은 까닭).
